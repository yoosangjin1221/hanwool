# Supabase 연결 설정 안내 — data10-06

이 폴더에는 이 도구의 로그인(가입 · 사용 신청 · 관리자 승인)을 **내 Supabase 프로젝트**에 연결하는 데 필요한 것이 모두 들어 있습니다.
순서대로 따라 하면 20분 안에 끝납니다.

| 파일 | 하는 일 | 언제 |
|---|---|---|
| `auth.sql` | 구성원 표 2개 · 판정 함수 5개 · 접근 정책 3개를 만듭니다. 이름이 모두 `data1006_` 로 시작합니다. | 처음 한 번(여러 번 실행해도 안전) |
| `board.sql` | 게시판 · 새 글 알림용 표 4개 · 함수 5개 · 정책 10개 · 트리거 2개. 이름이 모두 `data1006_board_` 로 시작합니다. | `auth.sql` 다음에 한 번(여러 번 실행해도 안전) |
| `site.sql` | 첫 화면 모양 설정용 표 1개 · 함수 1개 · 정책 2개. 이름이 모두 `data1006_site_` 로 시작합니다. | `auth.sql` 다음에 한 번(여러 번 실행해도 안전) |
| `verify.sql` | 제대로 만들어졌는지 숫자로 확인합니다. 읽기만 합니다. | SQL 실행 뒤, 문제가 생겼을 때 |
| `README.md` | 이 안내 | |

업무 자료(입력한 값 · 가져온 엑셀 · 결과)는 Supabase 에 올라가지 않습니다. 쓰는 사람의 브라우저에 저장됩니다.
Supabase 가 맡는 일은 두 가지입니다. 「누가 이 도구를 쓸 수 있는가」(로그인 · 승인)와 「팀 게시판 · 새 글 알림」입니다.

## 1. Supabase 프로젝트 만들기

1. https://supabase.com 에 로그인합니다.
2. 「New project」를 누릅니다.
   - Name: `data10-06` 처럼 알아보기 쉬운 이름
   - Database Password: 「Generate a password」로 만들고 **따로 적어 둡니다**. 이 도구에는 넣지 않습니다.
   - Region: `Northeast Asia (Seoul)`
3. 1~2분 기다리면 프로젝트가 열립니다.

무료 요금제로 충분합니다. 무료 프로젝트는 일주일 동안 아무도 쓰지 않으면 잠시 멈춥니다. 멈췄으면 대시보드에서 「Restore project」를 누르면 다시 켜집니다.

## 2. SQL 실행

1. 왼쪽 메뉴 「SQL Editor」 → 「New query」.
2. 이 폴더의 `auth.sql` 을 메모장 · VS Code 로 열어 **전체를 복사**해 붙여 넣습니다.
3. 맨 아래 §8 의 이메일 목록을 **내 이메일로 바꾸거나 비웁니다**.

   ```sql
   v_emails text[] := array['내이메일@회사.com']::text[];   -- 비우려면 array[]::text[]
   ```

   - 비워 두면 7번의 「첫 관리자 되기」 단추로 관리자를 정합니다. 이쪽이 더 쉽습니다.
4. 「Run」을 누릅니다. `Success. No rows returned` 가 나오면 됩니다.
5. 같은 방법으로 `verify.sql` 을 실행합니다. 첫 결과 한 줄이 아래와 같으면 정상입니다.

   | 칸 | 기대하는 값 |
   |---|---|
   | 표 | 2 |
   | RLS 켜진 표 | 2 |
   | 정책 | 3 |
   | 함수 | 5 |
   | 비로그인이 부를 수 있는 함수 | 0 |
   | 관리자 수 | 처음에는 0, 7번을 마치면 1 이상 |

`auth.sql` 은 `data1006_` 로 시작하는 것만 만들고 다른 표는 건드리지 않습니다. 이미 쓰고 있는 프로젝트에 넣어도 됩니다.

## 3. 로그인 방식 켜기(이메일)

「Authentication」 → 「Sign In / Providers」 → 「Email」.

- **Enable Email provider**: 켜져 있어야 합니다(처음부터 켜져 있습니다).
- **Confirm email**
  - 켜면: 가입한 사람이 메일의 확인 링크를 눌러야 로그인됩니다.
  - 끄면: 가입하자마자 로그인됩니다. 팀 안에서만 쓰고 어차피 관리자가 승인하므로, 처음에는 **끄는 것을 권합니다**.
  - Supabase 기본 메일은 한 시간에 보낼 수 있는 수가 아주 적습니다. 켜 둔 채 여러 명이 한꺼번에 가입하면 확인 메일이 오지 않을 수 있습니다.

## 4. 연결 링크 등록 — 내 사이트 주소 알려 주기

「Authentication」 → 「URL Configuration」.

내 사이트 주소가 `https://내아이디.github.io/data10-06/` 라면 이렇게 넣습니다.

| 칸 | 넣을 값 |
|---|---|
| Site URL | `https://내아이디.github.io/data10-06/` |
| Redirect URLs(「Add URL」) | `https://내아이디.github.io/data10-06/` |
| Redirect URLs(하나 더) | `https://내아이디.github.io/data10-06/**` |

- Redirect URLs 는 **두 줄 모두** 넣습니다. 끝에 `/**` 가 붙은 줄만 넣으면 맞지 않는 경우가 있습니다.
- 회사 서버나 다른 주소에 올렸다면 그 주소로 같은 모양 두 줄을 넣습니다.
- 내 PC 에서 로그인 화면까지 시험하려면 `http://localhost:8000/` 과 `http://localhost:8000/**` 도 넣습니다.
- 이 등록이 빠지면 메일 확인 링크나 카카오 로그인 뒤에 **다른 주소로 가 버립니다**. 「로그인이 안 된다」의 가장 흔한 원인입니다.

## 5. 중요 키 두 가지 찾기

이 도구에 넣는 값은 두 가지뿐입니다.

| 값 | 어디에 있나 | 생김새 |
|---|---|---|
| Project URL | 「Project Settings」 → 「Data API」(또는 프로젝트 첫 화면의 「Connect」) | `https://abcdefghijklmnop.supabase.co` |
| anon public 키 | 「Project Settings」 → 「API Keys」 → 「Legacy API Keys」 탭의 `anon` `public` | `eyJ…` 로 시작하는 긴 글자 |

메뉴 이름은 Supabase 화면이 바뀌면서 조금 달라질 수 있습니다. 「API」 「API Keys」 「Connect」 가운데 한 곳에 있습니다.

**넣으면 안 되는 키**

- `service_role` 키, `secret` 키(`sb_secret_…`): 모든 보호를 건너뛰는 키입니다. 웹 파일에 넣으면 누구나 볼 수 있으므로 **절대 넣지 않습니다**.
- Database Password, Access Token: 이 도구에는 쓰이지 않습니다.

anon public 키는 웹 페이지에 들어가도 되는 공개용 키입니다. 표마다 RLS(행 단위 보호)가 켜져 있어, 이 키만으로는 승인받지 않은 사람이 구성원 정보를 읽거나 고칠 수 없습니다.

## 6. `js/auth-config.js` 에 두 값 넣기

파일 맨 위 몇 줄만 고칩니다. 나머지(대문 문구 · 기능 소개)는 그대로 둡니다.

```js
window.AUTH_CONFIG = {
  "url": "https://abcdefghijklmnop.supabase.co",   // 5번의 Project URL
  "anonKey": "eyJ…",                               // 5번의 anon public 키
  "prefix": "data1006",                               // 그대로 둡니다(auth.sql 의 표 이름 앞부분)
  "kakao": false,                                  // 8번을 하지 않았다면 false
  "idleMinutes": 30,                               // 이만큼 아무 조작이 없으면 자동 로그아웃
  "localBypass": true,                             // 내 PC(localhost)에서는 로그인 생략
```

- 큰따옴표와 줄 끝 쉼표를 지우지 않게 조심합니다.
- 고친 뒤 깃허브에 올리고, 사이트를 열어 **Ctrl+F5**(맥은 Cmd+Shift+R)로 새로 고칩니다.
- 깃허브에 올리는 방법은 `docs/내_깃허브로_옮기기.md` 3번에 있습니다.

## 7. 첫 관리자 만들기

1. 내 사이트를 열고 「시작하기」 → 회원가입(이름 · 소속 · 연락처 · 이메일 · 비밀번호).
2. 로그인하면 「사용 신청」 화면이 나옵니다.
3. 관리자가 아직 한 명도 없으면 **「첫 관리자 되기」** 단추가 보입니다. 누르면 내가 관리자가 되고 도구가 열립니다.
   - 2번에서 `v_emails` 에 내 이메일을 넣었다면: 가입한 뒤 `auth.sql` 을 한 번 더 실행하면 관리자가 됩니다.
4. 그다음부터 가입하는 사람은 「승인 대기」가 되고, 관리자가 「관리」 화면에서 승인합니다. 관리자를 더 지정할 수도 있습니다.

## 8. (선택) 카카오 로그인

이메일 로그인만으로 충분하면 건너뜁니다(`"kakao": false`).

1. https://developers.kakao.com → 「내 애플리케이션」 → 애플리케이션 추가.
2. 「앱 키」의 **REST API 키**를 복사합니다.
3. 「카카오 로그인」을 켜고 **Redirect URI** 에 아래 주소를 넣습니다(내 사이트 주소가 아니라 Supabase 주소입니다).

   ```
   https://abcdefghijklmnop.supabase.co/auth/v1/callback
   ```

4. 「보안」에서 Client Secret 을 만들고 「사용함」으로 바꿉니다.
5. 「동의항목」에서 닉네임 · 이메일을 설정합니다. 이메일 항목은 앱 종류에 따라 추가 절차(비즈 앱 전환)가 필요할 수 있습니다.
6. Supabase 「Authentication」 → 「Sign In / Providers」 → 「Kakao」를 켜고 REST API 키(Client ID)와 Client Secret 을 넣습니다.
7. `js/auth-config.js` 의 `"kakao": true`.

## 10. 게시판 · 새 글 알림

로그인한 구성원이 함께 쓰는 게시판 하나와 새 글 알림입니다. 왼쪽 메뉴와 위쪽 줄에 「게시판」이 생깁니다.

| 기능 | 내용 |
|---|---|
| 게시판 | 글 목록 · 글 보기 · 글쓰기 · 고치기 · 지우기 · 댓글. 관리자는 글을 「공지」로 맨 위에 올릴 수 있습니다. |
| 새 글 알림 | 다른 사람이 글을 올리면 「게시판」 옆에 빨간 숫자가 뜨고, 화면 오른쪽 아래에 알림이 나옵니다. 목록에는 「새 글」 표시가 붙습니다. |
| 브라우저 알림 | 게시판에서 「브라우저 알림 켜기」를 누르면, 다른 탭을 보고 있을 때도 알림이 옵니다(도구를 열어 둔 동안). |

### 켜는 순서

1. 1~7번(로그인 연결)을 먼저 끝냅니다. `board.sql` 은 `auth.sql` 이 만든 구성원 판정을 씁니다.
2. 「SQL Editor」에 `board.sql` 전체를 붙여 넣고 「Run」. `Success. No rows returned` 가 나오면 됩니다.
3. `verify.sql` 을 다시 실행합니다. 둘째 결과가 아래와 같으면 정상입니다.

   | 칸 | 기대하는 값 |
   |---|---|
   | 게시판 표 | 4 |
   | RLS 켜진 표 | 4 |
   | 정책 | 10 |
   | 함수 | 5 |
   | 트리거 | 2 |
   | 비로그인이 부를 수 있는 함수 | 0 |

4. 도구를 새로 고치고(Ctrl+F5) 「게시판」을 엽니다. 글을 하나 써 봅니다.
5. 다른 계정(다른 브라우저나 시크릿 창)으로 로그인해 「게시판」 옆에 숫자 1 이 뜨는지 봅니다. 기본 확인 간격은 60초입니다.

`board.sql` 을 실행하기 전에는 「게시판」을 열면 실행 안내가 나옵니다. 도구의 다른 기능에는 영향이 없습니다.

### 설정 바꾸기 — Supabase 에서

「Table Editor」 → `data1006_board_settings` 표를 엽니다. 줄이 하나(`id` = 1) 있습니다. 칸을 눌러 고치고 저장하면 됩니다.

| 칸 | 뜻 | 넣을 수 있는 값 | 처음 값 |
|---|---|---|---|
| `board_name` | 게시판 이름(메뉴에도 이 이름이 보입니다) | 1~40자 | 게시판 |
| `write_role` | 글을 쓸 수 있는 사람 | `member`(승인된 구성원 모두) · `admin`(관리자만 = 공지 전용) | member |
| `comments_on` | 댓글 쓰기 | `true` · `false` | true |
| `notify_on` | 새 글 알림(숫자 · 화면 알림) | `true` · `false` | true |
| `poll_seconds` | 새 글을 확인하는 간격(초) | 20 ~ 3600 | 60 |

SQL 로 바꿔도 됩니다.

```sql
update public.data1006_board_settings
   set board_name = '공지사항', write_role = 'admin', poll_seconds = 30
 where id = 1;
```

관리자는 도구 안의 「게시판 → 설정」에서도 같은 값을 고칠 수 있습니다. 바꾼 값은 다음 확인 때(새로 고치면 바로) 반영됩니다.

### 표가 하는 일

| 표 | 내용 | 누가 |
|---|---|---|
| `data1006_board_posts` | 글(제목 · 내용 · 글쓴이 · 공지 여부) | 승인된 구성원이 읽고, 쓴 사람과 관리자가 고치고 지웁니다 |
| `data1006_board_comments` | 댓글 | 승인된 구성원이 읽고 쓰고, 쓴 사람과 관리자가 지웁니다 |
| `data1006_board_reads` | 사람마다 「어디까지 봤는가」 — 새 글 수의 기준 | 본인 줄만 |
| `data1006_board_settings` | 설정 한 줄 | 구성원이 읽고 관리자가 고칩니다 |

- 글쓴이 이름은 서버가 구성원 표에서 채웁니다. 화면에서 남의 이름으로 쓸 수 없습니다.
- 승인받지 않은 사람과 로그인하지 않은 사람은 글을 읽을 수 없습니다.
- 게시판을 끄려면 `js/auth-config.js` 에 `"board": false` 를 넣습니다. 표는 그대로 남습니다.
- 새 글 알림은 도구를 열어 둔 동안 일정 간격으로 확인하는 방식입니다. 메일 · 문자 발송은 하지 않습니다.

## 11. 첫 화면 모양 고르기

로그인 전에 보이는 맨 위 영역을 두 가지 가운데 골라 씁니다. 관리자가 때에 따라 바꿀 수 있습니다.

| 값 | 모양 |
|---|---|
| `auto` | 설정 파일(`js/auth-config.js` 의 `landing.heroMode`)에 적힌 모양을 따릅니다. (처음 값) |
| `design` | 회사 색 바탕에 실제 화면 카드와 떠 있는 기능 표시, 들어올 때 떠오르는 움직임. 사진이 없어도 됩니다. |
| `slide` | 사진 3장이 옆으로 넘어가는 슬라이드. 제목 · 설명 · 「로그인」 단추가 사진 위에 놓입니다. 아래 점과 화살표로 넘기고, 휴대폰에서는 손가락으로 넘깁니다. |

### 켜는 순서

1. 「SQL Editor」에 `site.sql` 전체를 붙여 넣고 「Run」.
2. `verify.sql` 을 실행합니다. 셋째 결과가 첫 화면 표·RLS 1 · 정책 2 · 비로그인 공개 함수 1 이면 정상입니다.
3. 관리자로 로그인해 왼쪽 메뉴 「첫 화면」을 엽니다. 모양과 사진이 넘어가는 간격(3~20초)을 고르고 저장합니다.
4. 로그아웃하거나 다른 브라우저(시크릿 창)에서 사이트를 열어 바뀐 첫 화면을 봅니다.

### Supabase 에서 바꾸기

「Table Editor」 → `data1006_site_settings` 표의 한 줄(`id` = 1)에서 `hero_mode` 를 `design` · `slide` · `auto` 가운데 하나로, `slide_seconds` 를 3~20 으로 고칩니다.

```sql
update public.data1006_site_settings set hero_mode = 'slide', slide_seconds = 6 where id = 1;
```

### 사진 바꾸기

- 사진은 저장소의 `images/slide-1.jpg` · `slide-2.jpg` · `slide-3.jpg` 입니다. 같은 이름으로 바꿔 올리면 됩니다.
- 가로로 긴 사진(가로 1920 × 세로 900 안팎)이 좋습니다. 왼쪽에 제목이 놓이므로 중요한 것은 가운데~오른쪽에 두면 가려지지 않습니다.
- 이름이나 장수를 바꾸려면 `js/auth-config.js` 의 `landing.slides` 목록을 고칩니다. 사진이 한 장도 없으면 `slide` 를 골라도 `design` 으로 보입니다.

### 알아 둘 것

- 로그인 전 화면이 이 값을 읽어야 해서 함수 `data1006_site_public()` 하나만 로그인하지 않은 사람에게 열려 있습니다. 이 함수는 모양과 간격 두 값만 돌려줍니다. 구성원 정보나 게시판 글은 볼 수 없습니다.
- `site.sql` 을 실행하지 않았으면 `js/auth-config.js` 의 `landing.heroMode` 값을 씁니다.
- 「움직임 줄이기」를 켠 기기에서는 사진이 자동으로 넘어가지 않습니다(화살표로 넘깁니다).

## 자주 나는 문제

| 보이는 것 | 원인 | 고치는 법 |
|---|---|---|
| `Invalid API key` | 키를 일부만 복사했거나 다른 프로젝트의 키 | 5번에서 anon public 키를 끝까지 다시 복사 |
| 로그인 · 메일 확인 뒤 엉뚱한 주소로 감 | 4번의 Redirect URLs 가 빠짐 | 내 사이트 주소 두 줄(끝 `/` 와 `/**`)을 등록 |
| 가입했는데 확인 메일이 안 옴 | 기본 메일 발송 한도 | 3번의 Confirm email 을 끄거나 잠시 뒤 다시 |
| `relation "public.data1006_members" does not exist` | `auth.sql` 을 실행하지 않았거나 `prefix` 를 바꿈 | 2번을 다시, `prefix` 는 `data1006` 그대로 |
| 가입했는데 계속 「승인 대기」 | 관리자가 아직 승인하지 않음 | 관리자가 「관리」에서 승인. 관리자가 없으면 7번 |
| 「첫 관리자 되기」가 안 보임 | 이미 관리자가 있음 | `verify.sql` 둘째 결과에서 관리자가 누구인지 확인 |
| 고쳤는데 그대로임 | 브라우저가 옛 파일을 쓰는 중 | Ctrl+F5, 그래도 같으면 판을 올림(`docs/내_깃허브로_옮기기.md` 4번) |
| 「게시판 준비가 필요합니다」 | `board.sql` 을 실행하지 않음 | 10번의 2 |
| 글을 올렸는데 다른 사람에게 숫자가 안 뜸 | 확인 간격 전이거나 알림이 꺼짐 | 1분 기다리거나 새로 고침, `notify_on` 이 true 인지 확인 |
| 「글을 쓸 권한이 없습니다」 | `write_role` 이 admin(공지 전용) | 설정에서 member 로 바꾸거나 관리자가 씀 |
| 「첫 화면」에서 저장 단추가 눌리지 않음 | `site.sql` 을 실행하지 않음 | 11번의 1 |
| `slide` 로 바꿨는데 그대로임 | 사진이 없거나 브라우저가 옛 값을 기억함 | `images/slide-1.jpg` 가 있는지 확인, 새로 고침 |
| 며칠 뒤 로그인이 안 됨 | 무료 프로젝트가 멈춤 | 대시보드에서 「Restore project」 |

## 지금 열려 있는 주소는

과정 중에 쓰던 주소는 과정용 Supabase 프로젝트에 연결돼 있습니다. 내 프로젝트로 옮기면 구성원은 새로 가입하고 승인합니다(업무 자료는 브라우저에 있으므로 「설정 → 백업」으로 옮깁니다).
