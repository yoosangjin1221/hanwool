# 내 깃허브 · 내 Supabase 로 옮기기 — data10-06

이 도구는 빌드 과정이 없는 정적 사이트(HTML · CSS · JS)입니다. 폴더를 통째로 내 깃허브 저장소에 올리고, 로그인용 Supabase 프로젝트를 하나 만들어 연결하면 그대로 돌아갑니다.

## 무엇이 어디에 저장되나

| 구분 | 저장 위치 | 옮길 때 |
|---|---|---|
| 업무 자료(입력 · 가져온 엑셀 · 결과) | 쓰는 사람의 브라우저(localStorage) | 화면의 「설정 → 백업(JSON)」으로 내려받아 새 주소에서 다시 불러오기 |
| 누가 쓸 수 있는가(가입 · 승인 · 관리자) | Supabase 표 `data1006_members` · `data1006_member_changes` | 새 프로젝트에서 SQL 한 번 실행, 구성원은 새로 가입 · 승인 |
| 화면 · 계산 코드 | 이 저장소 파일 | 그대로 복사 |

## 1. 내 Supabase 프로젝트 만들기

1. https://supabase.com 에 가입하고 「New project」를 만듭니다(무료 요금제로 충분합니다).
2. 왼쪽 「SQL Editor」에서 이 저장소의 `supabase/auth.sql` 내용을 붙여 넣고 「Run」을 누릅니다.
   - 맨 아래 `v_emails` 목록에 내 이메일을 넣어 두면, 그 이메일로 가입한 뒤 SQL 을 한 번 더 실행했을 때 관리자가 됩니다.
   - 목록을 비워 둬도 됩니다. 관리자가 한 명도 없으면 처음 로그인한 사람에게 「첫 관리자 되기」 단추가 보입니다.
   - 여러 번 실행해도 안전합니다.
3. 「Authentication → Sign In / Providers → Email」이 켜져 있는지 봅니다.
   - 「Confirm email」을 켜 두면 가입한 사람이 메일의 확인 링크를 눌러야 로그인할 수 있습니다. 회사 안에서만 쓰면 꺼 두는 편이 편합니다.
4. 「Authentication → URL Configuration」의 Site URL 과 Redirect URLs 에 내 사이트 주소를 넣습니다(예: `https://내아이디.github.io/data10-06/` 과 `https://내아이디.github.io/data10-06/**`).
5. 「Project Settings → API」에서 **Project URL** 과 **anon public** 키를 복사합니다. anon 키는 공개해도 되는 키입니다(표마다 RLS 로 막혀 있습니다). `service_role` 키는 절대 넣지 마세요.

## 2. 설정 파일 한 곳 바꾸기 — `js/auth-config.js`

```js
url: 'https://<내 프로젝트>.supabase.co',
anonKey: '<anon public 키>',
kakao: false,          // 카카오 로그인을 따로 설정하지 않았다면 false
```

`prefix`(`data1006`)는 그대로 둡니다 — SQL 의 표 이름과 같아야 합니다.

## 3. 내 깃허브에 올리기

1. GitHub 에서 새 저장소를 만듭니다(Private 권장).
2. 이 폴더의 파일을 모두 올립니다. `CNAME` 파일이 있으면 지웁니다(원래 주소용입니다).
   - `index.html` 위쪽 「seo-kit」 묶음의 주소 3곳(`canonical` · `og:url` · `og:image`)을 내 사이트 주소로 바꿉니다. 카카오톡 등에 주소를 붙였을 때 뜨는 미리보기용입니다.
3. 저장소 「Settings → Pages」에서 Source 를 `main` 브랜치 `/ (root)` 로 고르면 `https://내아이디.github.io/data10-06/` 에 열립니다.
   비공개 저장소의 Pages 는 유료 요금제에서만 됩니다. 무료라면 공개 저장소로 하거나 회사 서버에 파일을 올리세요.
4. 처음 들어가 가입 → (관리자 지정) → 함께 쓸 사람들이 가입하면 「구성원 관리」에서 승인합니다.

## 4. 고칠 때 지킬 것

- js · css 를 고치면 판을 올립니다: `node scripts/bump-version.mjs` — 브라우저가 옛 파일과 새 파일을 섞어 쓰지 않게 합니다.
- 계산 규칙 시험: `node test/logic.test.mjs`
- 내 PC 에서 볼 때(`python3 -m http.server 8000` → `http://localhost:8000`)는 로그인을 건너뜁니다. 로그인 화면을 보려면 주소 끝에 `?auth=1` 을 붙입니다.
- `js/auth.js` · `css/auth.css` 는 로그인 키트입니다. 고쳐도 되지만, 고친 뒤에는 가입 → 신청 → 승인 → 관리자 지정 → 로그아웃을 한 번씩 해 보세요.
